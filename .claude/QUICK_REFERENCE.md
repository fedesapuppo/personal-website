# Quick Reference Guide

## 🚀 Commands (Use with /)

| Command | Description | When to Use |
|---------|-------------|-------------|
| `/full-resume-audit` | Complete audit (4 agents in parallel) | Before deployment, major changes |
| `/quick-improve` | Fast interactive improvements | During development |
| `/improve-content` | Content-focused improvements | Refining work descriptions |
| `/deploy-check` | Pre-deployment validation | Before pushing live |

## 🎯 Skills (Activate Automatically)

| Skill | Trigger Phrases | What It Does |
|-------|----------------|--------------|
| `accessibility-audit` | "check accessibility", "audit WCAG" | Full a11y audit with report |
| `responsive-check` | "test mobile", "check responsive" | Test all viewport sizes |
| `add-section` | "add projects section", "add testimonials" | Add new content sections |

## 🤖 Agents (Used by Commands/Skills)

| Agent | Model | Specialty |
|-------|-------|-----------|
| `content-analyzer` | Sonnet | Resume content quality |
| `seo-optimizer` | Haiku | SEO & metadata |
| `design-reviewer` | Sonnet | UX/UI & accessibility |
| `performance-auditor` | Haiku | Loading speed |

## 📖 Common Workflows

### First Time Setup
```bash
# 1. Run full audit
/full-resume-audit

# 2. Review report
cat AUDIT_REPORT.md

# 3. Fix critical issues
/quick-improve

# 4. Deploy
/deploy-check
```

### Quick Iteration
```bash
# Make a change to index.html
# Then test specific area:
/quick-improve
→ Choose area
→ Apply fixes
```

### Adding Content
```
Just say: "Add a projects portfolio section"
→ add-section skill activates
→ Answer questions about content
→ Review generated code
→ Approve to apply
```

## 💡 Pro Tips

1. **Parallel Agents** - `/full-resume-audit` spawns 4 agents at once for speed
2. **Model Selection** - Sonnet for analysis, Haiku for speed
3. **Auto-activation** - Skills trigger automatically from conversation
4. **Reports Saved** - All audits save to project root
5. **Incremental** - Use `/quick-improve` for rapid iteration
